# Sage X3 Customizations

A collection of custom Sage X3 development work, including Adonix 4GL source code, Microsoft SQL Server queries, and custom projects.

This repository contains solutions I've developed while working with Sage X3, shared in the hope that they may serve as useful examples, references, or starting points for other developers working with the platform.

## Overview

I began learning Sage X3 development independently, teaching myself the Adonix 4GL language through experimentation, documentation, and practical problem-solving.

Over time, that work grew into a collection of custom programs, database queries, and integrations designed to extend Sage X3 functionality, simplify business processes, and address requirements not readily accommodated by standard functionality.

Rather than keeping these solutions exclusively to myself, I've made them available here for anyone who might find them useful.

## Repository Structure

| Directory | Description |
|---|---|
| `ADONIX/` | Custom Sage X3 Adonix 4GL source code (`.src` files). |
| `SQL/` | Microsoft SQL Server queries and scripts relating to Sage X3 data. |
| `PROJECTS/` | Larger customizations and projects combining Adonix development with SQL views or other supporting components. |

## Development Environment

The source code in this repository has primarily been developed in the following environment:

- **ERP:** Sage X3 Version 11
- **Language:** Adonix 4GL
- **Database:** Microsoft SQL Server 2016
- **Development Tools:** SAFE X3 Studio, SQL Server Management Studio, and other development utilities

Compatibility with other Sage X3 versions, database platforms, or environments is not guaranteed.

## Using This Repository

The contents of this repository are intended to be used as development references and examples.

You are welcome to study, adapt, and incorporate the original code into your own Sage X3 customizations, subject to the MIT License and any applicable third-party rights.

Some programs may reference custom tables, fields, screens, entry points, SQL views, or other components that are specific to the environment in which they were developed.

Consequently, not every program will function as-is in another Sage X3 installation.

Before implementing any code:

1. Review the source and understand its functionality.
2. Identify any environment-specific dependencies.
3. Adapt the program to your Sage X3 configuration and version.
4. Test thoroughly in a development or test environment.
5. Validate data integrity, transaction handling, and error conditions before deploying to production.

The examples are provided as reference implementations rather than universally applicable, production-ready solutions.
